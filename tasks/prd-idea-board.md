# PRD: Idea Board — борда идей для контент-криейтора

## Введение

**Idea Board** — веб-приложение, где аудитория контент-криейтора (YouTube, Telegram) может предлагать темы для контента, голосовать за чужие идеи и отслеживать их реализацию. По сути — перманентный кастдев: идеи копятся, голоса накапливаются, криейтор видит, что аудитории реально нужно.

**Проблема:** Идеи для контента приходят хаотично — в комментариях, личных сообщениях, на созвонах. Они теряются, дублируются, нет понимания приоритетов. Нет единого места, где аудитория может влиять на контент-план.

**Решение:** Одностраничное приложение с голосованием, где каждый подписчик может предложить тему или поддержать существующую, а криейтор видит ранжированный список потребностей аудитории.

**Владелец:** Один инстанс для одного криейтора (olezhek28).

---

## Цели

- Собрать все идеи для контента в одном месте с прозрачной приоритизацией
- Дать аудитории ощущение влияния на контент-план ("я за это голосовал → видео вышло")
- Снизить шум: дубликаты, мусор, размытые запросы — отфильтровываются
- Замкнуть петлю обратной связи: идея → голосование → реализация → ссылка на результат
- Накопить кумулятивную базу потребностей аудитории

---

## Пользовательские роли

| Роль | Описание |
|------|----------|
| **Гость** | Видит список идей, может читать. Не может голосовать или предлагать |
| **Пользователь** | Авторизован через Telegram. Может голосовать, предлагать идеи |
| **Админ** | Криейтор (один). Управляет статусами, мержит, удаляет, модерирует |

## User Stories

### US-001: Просмотр списка идей (Гость / Пользователь)

**Описание:** Как посетитель, я хочу видеть список идей с голосами, чтобы понять, что аудитория хочет больше всего.

**Acceptance Criteria:**
- [ ] Главная страница отображает список идей в виде карточек
- [ ] Каждая карточка содержит: заголовок, категорию, количество голосов, статус, автора (имя из Telegram)
- [ ] Три режима сортировки: "Популярное" (по голосам за всё время), "Трендовое" (по голосам за последние 7 дней), "Новое" (по дате создания)
- [ ] Фильтрация по категории: Все / YouTube / Telegram / Курс / Инструмент
- [ ] Фильтрация по статусу: Все / Новая / В планах / В работе / Сделано
- [ ] Поиск по тексту (заголовок + описание)
- [ ] У идей со статусом "Сделано" отображается ссылка на результат (видео/пост)
- [ ] Пагинация или infinite scroll при большом количестве идей
- [ ] Verify in browser using dev-browser skill

### US-002: Авторизация через Telegram-бота (Гость)

**Описание:** Как гость, я хочу войти через Telegram в один шаг, чтобы сразу голосовать, предлагать идеи и получать уведомления.

**Acceptance Criteria:**
- [ ] На странице есть кнопка "Войти через Telegram"
- [ ] При клике генерируется уникальный `auth_token` и пользователь перенаправляется на `t.me/<bot_username>?start=auth_<token>`
- [ ] В Telegram открывается бот. Пользователь нажимает "Start" (или "Запустить")
- [ ] Бот получает `/start auth_<token>` через webhook
- [ ] Бот сохраняет `telegram_id`, `chat_id`, `username`, `first_name`, `photo_url` и привязывает к `auth_token`
- [ ] Бот отвечает приветственным сообщением: "Авторизация прошла! Возвращайся на сайт. Я буду присылать уведомления о твоих идеях и голосах. /mute — отключить"
- [ ] На фронте — polling `/api/auth/check?token=<token>` каждые 2 секунды (макс. 2 минуты, потом таймаут)
- [ ] Когда бот подтвердил авторизацию — API возвращает JWT, фронт ставит cookie и обновляет UI
- [ ] Отображается аватар и имя пользователя из Telegram
- [ ] Кнопка "Выйти" сбрасывает сессию
- [ ] При первой авторизации: создаётся пользователь с 5 голосами, `bot_started = true`
- [ ] `auth_token` одноразовый, истекает через 5 минут
- [ ] Verify in browser using dev-browser skill

### US-003: Голосование за идею (Пользователь)

**Описание:** Как авторизованный пользователь, я хочу голосовать за идеи, чтобы повлиять на контент-план.

**Acceptance Criteria:**
- [ ] Кнопка голоса на каждой карточке идеи (стрелка вверх / +1)
- [ ] Клик по кнопке тратит 1 голос из бюджета пользователя
- [ ] Повторный клик снимает голос (возвращает в бюджет)
- [ ] Нельзя проголосовать дважды за одну идею
- [ ] Отображается текущий баланс голосов пользователя ("Осталось голосов: 7/10")
- [ ] Если голосов 0 — кнопка неактивна, tooltip объясняет механику регенерации
- [ ] Голоса анимируются при клике (микро-анимация счётчика)
- [ ] Verify in browser using dev-browser skill

### US-004: Система бюджета голосов (Пользователь)

**Описание:** Как пользователь, я хочу получать голоса со временем, чтобы продолжать влиять на приоритеты.

**Acceptance Criteria:**
- [ ] При регистрации: 5 голосов
- [ ] Каждые 24 часа начисляется +1 голос (серверный cron или при логине)
- [ ] Максимум накопления: 10 голосов
- [ ] Отданные голоса не теряются при регенерации (бюджет = неиспользованные)
- [ ] При снятии голоса с идеи — голос возвращается в бюджет (не выше максимума)
- [ ] В профиле видно: текущий баланс, сколько голосов отдано, когда следующее начисление

### US-005: Создание идеи (Пользователь)

**Описание:** Как пользователь, я хочу предложить новую тему для контента.

**Acceptance Criteria:**
- [ ] Кнопка "Предложить идею" доступна только авторизованным
- [ ] Форма создания: заголовок (обязательно, макс. 100 символов), описание "Почему это важно?" (обязательно, мин. 30 символов, макс. 500), категория (выбор из списка)
- [ ] Лимит: 3 идеи в месяц. Отображается счётчик "Осталось идей в этом месяце: 2/3"
- [ ] При исчерпании лимита кнопка "Предложить идею" неактивна с пояснением
- [ ] Перед отправкой — поиск похожих идей (по заголовку, fuzzy match). Если найдены — предложить проголосовать за существующую
- [ ] После отправки — идея уходит на модерацию (статус "На модерации", не видна другим)
- [ ] Пользователь видит свои идеи на модерации в личном разделе с пометкой "Ожидает модерации"
- [ ] Уведомление в Telegram боте когда идея одобрена или отклонена
- [ ] Verify in browser using dev-browser skill

### US-006: Пре-модерация идей (Админ)

**Описание:** Как админ, я хочу проверять новые идеи перед публикацией, чтобы не допускать мусор и оскорбления.

**Acceptance Criteria:**
- [ ] Админ-панель: раздел "На модерации" с очередью новых идей
- [ ] Каждая идея: заголовок, описание, автор (Telegram username), дата
- [ ] Действия: "Одобрить" (публикует), "Отклонить" (удаляет, автор получает уведомление), "Редактировать и одобрить" (поправить текст перед публикацией)
- [ ] Уведомление админу в Telegram при поступлении новой идеи на модерацию
- [ ] Verify in browser using dev-browser skill

### US-007: Управление статусами (Админ)

**Описание:** Как админ, я хочу менять статусы идей, чтобы аудитория видела прогресс.

**Acceptance Criteria:**
- [ ] Статусы: `Новая` → `В планах` → `В работе` → `Сделано`
- [ ] При переходе в "Сделано" — обязательное поле "Ссылка на результат" (URL видео/поста)
- [ ] При смене статуса — уведомление всем проголосовавшим через Telegram бота
- [ ] Визуальное различие статусов на карточках (цвет/бейдж)
- [ ] Verify in browser using dev-browser skill

### US-008: Мерж дубликатов (Админ)

**Описание:** Как админ, я хочу объединять похожие идеи, чтобы голоса не размазывались.

**Acceptance Criteria:**
- [ ] В админке: выбрать 2+ идеи → "Объединить"
- [ ] Одна идея становится главной, остальные помечаются как "Объединена с #ID"
- [ ] Голоса со всех объединённых идей суммируются на главной
- [ ] Пользователи, голосовавшие за дубликаты, видят, что их голос перенесён
- [ ] Verify in browser using dev-browser skill

### US-009: Telegram-бот уведомления (Пользователь)

**Описание:** Как пользователь, я хочу получать уведомления в Telegram, когда что-то происходит с моими идеями/голосами.

**Acceptance Criteria:**
- [ ] Бот автоматически может слать сообщения (пользователь нажал /start при авторизации)
- [ ] Типы уведомлений:
  - Идея, за которую голосовал, сменила статус (особенно "Сделано" + ссылка)
  - Идея, которую создал, одобрена / отклонена
  - За идею, которую создал, проголосовало N человек (пороги: 5, 10, 25, 50, 100)
- [ ] Пользователь может отключить уведомления командой /mute в боте
- [ ] Команда /unmute — включить уведомления обратно

### US-010: Архив идей (Админ)

**Описание:** Как админ, я хочу видеть архивированные идеи и при необходимости возвращать их в активный список.

**Acceptance Criteria:**
- [ ] Идеи с 0 голосами старше 3 месяцев автоматически переносятся в статус `archived`
- [ ] Архивированные идеи не видны в основном списке для пользователей
- [ ] В админке есть раздел "Архив" со списком архивированных идей
- [ ] Админ может вернуть идею из архива в статус "Новая"
- [ ] Админ может окончательно удалить архивированную идею
- [ ] Verify in browser using dev-browser skill

### US-011: i18n — поддержка двух языков

**Описание:** Как разработчик, я хочу заложить мультиязычность с самого начала.

**Acceptance Criteria:**
- [ ] Русский — язык по умолчанию
- [ ] Все строки интерфейса вынесены в файлы переводов (JSON: `ru.json`, `en.json`)
- [ ] Переключатель языка в header (RU / EN)
- [ ] Язык сохраняется в cookie / localStorage
- [ ] Контент идей (заголовки, описания) НЕ переводится — остаётся на языке автора

## Функциональные требования

### Авторизация и пользователи

- **FR-01:** Авторизация через Telegram-бота. Бот регистрируется через @BotFather. Webhook устанавливается на `https://ideas.olezhek28.courses/api/bot/webhook`
- **FR-02:** Флоу авторизации:
  1. Фронт вызывает `POST /api/auth/init` → получает `auth_token` (UUID, TTL 5 минут)
  2. Фронт редиректит на `t.me/<bot>?start=auth_<token>`
  3. Telegram доставляет `/start auth_<token>` на webhook бота
  4. Бот извлекает `telegram_id`, `chat_id`, `username`, `first_name`, `photo_url` из объекта `message.from`
  5. Бот сохраняет данные в БД, привязывает к `auth_token`, помечает токен как подтверждённый
  6. Бот шлёт приветственное сообщение пользователю
  7. Фронт поллит `GET /api/auth/check?token=<token>` каждые 2 сек
  8. Когда токен подтверждён — API возвращает JWT
- **FR-03:** Сессия хранится в JWT (httpOnly cookie, SameSite=Strict, Secure). Срок жизни — 30 дней
- **FR-04:** При первой авторизации создаётся запись пользователя: `telegram_id`, `chat_id`, `username`, `first_name`, `photo_url`, `votes_balance = 5`, `bot_started = true`
- **FR-05:** Роль админа определяется по `telegram_id` из переменной окружения `ADMIN_TELEGRAM_ID`
- **FR-28:** Таблица `auth_tokens` для хранения pending-авторизаций: `token` (UUID), `telegram_id` (null пока не подтверждён), `confirmed` (boolean), `expires_at`, `created_at`

### Идеи

- **FR-06:** Создание идеи: `title` (varchar 100), `description` (text, 30-500 символов), `category` (enum: youtube, telegram, course, tool)
- **FR-07:** Статусы идеи: `moderation` → `new` → `planned` → `in_progress` → `done`. Дополнительный статус: `archived`. Начальный статус — `moderation`
- **FR-08:** При статусе `done` обязательно поле `result_url` (ссылка на видео/пост)
- **FR-09:** Поиск похожих идей при создании: `LIKE '%keyword%'` по заголовку (для MVP). Показывать топ-3 совпадения
- **FR-10:** Мерж идей: голоса переносятся на главную идею, дубликат помечается `merged_into_id`

### Голосование

- **FR-11:** Один голос = один пользователь на одну идею. Голос можно отозвать
- **FR-12:** Бюджет голосов: начальный = 5, регенерация = +1 каждые 24 часа, максимум = 10
- **FR-13:** Регенерация голосов: при каждом запросе к API проверяется `last_vote_regen_at`. Если прошло ≥24ч — начислить голоса (ленивое начисление, без cron)
- **FR-14:** Trending-сортировка: считать голоса, отданные за последние 7 дней (отдельный запрос с `WHERE voted_at > NOW() - 7 days`)

### Уведомления (Telegram Bot)

- **FR-15:** Бот использует Telegram Bot API (`sendMessage`). `chat_id` сохраняется при авторизации (пользователь нажимает /start как часть auth-флоу → бот сразу может писать)
- **FR-16:** `bot_started` всегда `true` для авторизованных пользователей (авторизация = /start в боте). Поле сохраняется на случай если пользователь заблокирует бота — при ошибке `sendMessage` ставим `bot_started = false`
- **FR-17:** Типы уведомлений: смена статуса идеи, одобрение/отклонение идеи, пороги голосов (5/10/25/50/100), новая идея на модерации (для админа)
- **FR-18:** Команда `/mute` — отключает все уведомления. `/unmute` — включает обратно
- **FR-19:** Rate limiting на отправку уведомлений: не более 30 сообщений в секунду (лимит Telegram API)

### Лимит идей и архивация

- **FR-24:** Лимит создания идей: 3 идеи в месяц на пользователя. Счётчик `ideas_this_month` сбрасывается лениво — при создании идеи проверяется `ideas_month_reset`, если текущий месяц отличается — сброс на 0
- **FR-25:** При попытке создать идею сверх лимита — показать сообщение "Вы исчерпали лимит идей в этом месяце (3/3). Новые идеи можно предлагать с 1-го числа следующего месяца"
- **FR-26:** Автоматическая архивация: при каждом запросе к списку идей (или по cron раз в сутки) — идеи с `votes_count = 0` и `created_at < NOW() - 3 months` переводятся в статус `archived`
- **FR-27:** Архивированные идеи не отображаются в основном списке. Доступны админу в разделе "Архив" в админ-панели. Админ может вернуть идею из архива (сменить статус обратно на `new`)

### Админ-панель

- **FR-20:** Доступ к админке по маршруту `/admin`, проверка роли на сервере (middleware)
- **FR-21:** Очередь модерации: список идей со статусом `moderation`. Действия: одобрить, отклонить, редактировать + одобрить
- **FR-22:** Управление идеями: смена статуса, редактирование, удаление, мерж дубликатов
- **FR-23:** Дашборд (базовый): общее количество идей, пользователей, голосов. Топ-5 идей

## Нефункциональные требования

- **NFR-01:** Время отклика страницы < 200мс (SSR + SQLite на том же сервере)
- **NFR-02:** Мобильная адаптивность (брейкпоинты: 960px, 640px)
- **NFR-03:** SEO: meta-теги, Open Graph для шеринга
- **NFR-04:** Защита от спама: rate limiting на создание идей (макс. 3 идеи в час на пользователя)
- **NFR-05:** Безопасность: CSRF-токены, SQL-инъекции (параметризованные запросы), XSS (экранирование)
- **NFR-06:** Бэкап SQLite: автоматическое копирование файла БД (можно через cron на VPS)

### Схема базы данных

```sql
-- Пользователи
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    telegram_id INTEGER UNIQUE NOT NULL,
    chat_id INTEGER NOT NULL,               -- для отправки сообщений ботом
    username TEXT,
    first_name TEXT NOT NULL,
    photo_url TEXT,
    votes_balance INTEGER NOT NULL DEFAULT 5,
    last_vote_regen_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    ideas_this_month INTEGER NOT NULL DEFAULT 0,
    ideas_month_reset TEXT NOT NULL DEFAULT (strftime('%Y-%m', 'now')),  -- 'YYYY-MM' для отслеживания сброса
    bot_started BOOLEAN NOT NULL DEFAULT 0,
    notifications_enabled BOOLEAN NOT NULL DEFAULT 1,
    is_admin BOOLEAN NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- Идеи
CREATE TABLE ideas (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL CHECK(length(title) <= 100),
    description TEXT NOT NULL CHECK(length(description) >= 30 AND length(description) <= 500),
    category TEXT NOT NULL CHECK(category IN ('youtube', 'telegram', 'course', 'tool')),
    status TEXT NOT NULL DEFAULT 'moderation' CHECK(status IN ('moderation', 'new', 'planned', 'in_progress', 'done', 'archived')),
    result_url TEXT,
    author_id INTEGER NOT NULL REFERENCES users(id),
    merged_into_id INTEGER REFERENCES ideas(id),
    votes_count INTEGER NOT NULL DEFAULT 0,  -- денормализованный счётчик для быстрой сортировки
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- Голоса
CREATE TABLE votes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL REFERENCES users(id),
    idea_id INTEGER NOT NULL REFERENCES ideas(id),
    voted_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(user_id, idea_id)
);

-- Токены авторизации (pending auth flow)
CREATE TABLE auth_tokens (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    token TEXT UNIQUE NOT NULL,             -- UUID
    telegram_id INTEGER,                    -- null пока не подтверждён
    chat_id INTEGER,                        -- chat_id для бота
    confirmed BOOLEAN NOT NULL DEFAULT 0,
    expires_at DATETIME NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_auth_tokens_token ON auth_tokens(token);

-- Уведомления (лог, для дедупликации и порогов)
CREATE TABLE notifications (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL REFERENCES users(id),
    idea_id INTEGER REFERENCES ideas(id),
    type TEXT NOT NULL,  -- 'status_change', 'idea_approved', 'idea_rejected', 'vote_milestone', 'new_moderation'
    sent_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- Индексы
CREATE INDEX idx_ideas_status ON ideas(status);
CREATE INDEX idx_ideas_category ON ideas(category);
CREATE INDEX idx_ideas_votes_count ON ideas(votes_count DESC);
CREATE INDEX idx_ideas_created_at ON ideas(created_at DESC);
CREATE INDEX idx_votes_idea_id ON votes(idea_id);
CREATE INDEX idx_votes_voted_at ON votes(voted_at);
CREATE INDEX idx_votes_user_idea ON votes(user_id, idea_id);
```

- Идеи поступают: ≥20 идей за первый месяц

## Решённые вопросы

1. **Домен:** `ideas.olezhek28.courses`
2. **Telegram Bot:** Новый бот (не смешивать с существующим `olezhek28-courses-bot`)
3. **Лимит идей:** Да — 3 идеи в месяц на пользователя. Счётчик сбрасывается 1-го числа каждого месяца
4. **Архивация:** Автоматическая — идеи с 0 голосами старше 3 месяцев переносятся в статус `archived`. Не удаляются, доступны админу в разделе "Архив"
5. **Авторизация:** Через deep link в Telegram-бота (`t.me/bot?start=auth_TOKEN`), не через Login Widget. Один шаг = и авторизация, и разрешение на уведомления
6. **Onboarding-текст:** Да — бот отвечает на /start: "Авторизация прошла! Возвращайся на сайт. Я буду присылать уведомления о твоих идеях и голосах. /mute — отключить"
